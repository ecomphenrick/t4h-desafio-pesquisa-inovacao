# Bug na coluna cpu_max do recursos.txt gerado por scripts/medir.sh
# data: 2026-11-20 00:51:56 -0300   commit: 746ac32
#
# Sintoma: em resultados/20261120-002731-04-pool-conexoes/recursos.txt a cpu_media do banco (100.2%) e maior que a cpu_max (99.4%).
# Na API isso acontece em todas as medicoes (ex.: cpu_media 18.0%, cpu_max 9.8%).
#
# Causa: scripts/medir.sh:106-109 remove o % com gsub e compara o valor como TEXTO.
# Em ordem de texto, "99.4" > "108.8" (o caractere 9 vem depois do 1), entao o maximo
# fica errado sempre que existem amostras com numero de digitos diferente (>= 10% ou >= 100%).
# A media nao e afetada: soma_cpu += cpu converte para numero.
#
# Consequencia: cpu_max nao e confiavel e nao e usada no experimentos.md nem no artigo.
# Toda comparacao de CPU usa cpu_media. O maximo real pode ser tirado do recursos.csv.
# scripts/ e a regua do desafio e nao foi alterado.

# comando: sed -n 105,110p scripts/medir.sh
  NR > 1 {
    nome = $2; cpu = $3; gsub(/%/, "", cpu)
    split($4, partes, " / "); memoria = mib(partes[1])
    amostras[nome]++; soma_cpu[nome] += cpu; soma_mem[nome] += memoria
    if (cpu > max_cpu[nome]) max_cpu[nome] = cpu
    if (memoria > max_mem[nome]) max_mem[nome] = memoria
